Currently all the work done on the orchestrator workflow is done with sequential single agents. The natural next step for the skill is to start doing parallel work. Ochestrating paralel work done by sub agents would require a pricise task scope slicing to avoid to much overlap between sub agents what would require more effort to reconcile the results and would decrease the overall efficiency of the workflow. I think that for fullstack and mobile projects, the separtion over different layers (e.g. frontend, backend, mobile) would be a good way to start the slice of the task scope for parallel work. The orchestrator should create a well define separation between sub agents to avoid overlap and ensure efficient parallel work and it should be done by a contract that would define the scope and most importantly the interface between the sub agents work so the results can be reconciled efficiently. The parallelization should be an option, for optimizing time, the orchestrator should ask the user for the level of parallelization presenting options always evaluating the cost efficiency of spliting the scope and creating such contract that each subagent could feed on and the possible speed gain from parallelization.
