my idea of the full parallel mode on the orchestrator was to get inner lane parallelization too. For example in a fullstack + mobile monorepo, it could identify backend, frontend, and mobile lanes, but besides that, it could devide the frontend and mobile into ui, business logic and data modeling/integration; on backend it could identify presentation layer (controller for nestjs, viewset for django), data modeling, business logic, so on. So the full parallel mode would allow the orchestrator to spawn parallel inner lane executions, but following the same criteria of the lane mode. The parallelization would be evaluated against the cost efficiency optics, based on a contract to minimize conciliation work. Does it accomodate into the current parallelization propose?
